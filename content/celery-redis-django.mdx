Django applications often need to handle time-consuming tasks without blocking the main request-response cycle. This guide explores how to implement asynchronous task processing with Celery and Redis.

## Introduction

In web applications, certain operations like sending emails, processing large files, or generating reports can be 
time-consuming. Performing these tasks synchronously during HTTP requests leads to poor user experience and 
potential timeouts. Celery, combined with Redis as a message broker, provides a robust solution for handling 
background tasks in Django applications, improving performance and user experience.

## Why Celery and Redis Matter

Implementing asynchronous task processing with Celery and Redis offers several advantages:

- **Improved Response Times**: Offload time-consuming tasks to background workers
- **Scalability**: Easily scale task processing by adding more worker instances
- **Reliability**: Retry mechanisms for failed tasks and task result storage
- **Scheduled Tasks**: Schedule periodic tasks without relying on cron jobs
- **Distributed Processing**: Distribute tasks across multiple servers

## Setting Up Celery with Redis in Django

Let's start by setting up Celery with Redis in a Django project:


### Configuring Celery

First, create a `celery.py` file in your project directory:

```python
# myproject/celery.py
import os
from celery import Celery

# Set the default Django settings module
os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'myproject.settings')

# Create the Celery app
app = Celery('myproject')

# Load configuration from Django settings
app.config_from_object('django.conf:settings', namespace='CELERY')

# Auto-discover tasks in all installed apps
app.autodiscover_tasks()

@app.task(bind=True, ignore_result=True)
def debug_task(self):
    print(f'Request: {self.request!r}')
```

Next, update your project's `__init__.py` to ensure Celery is loaded when Django starts:

```python
# myproject/__init__.py
from .celery import app as celery_app

__all__ = ('celery_app',)
```

### Configuring Django Settings

Update your Django settings to include Celery and Redis configuration:

```python
# myproject/settings.py

# Celery settings
CELERY_BROKER_URL = 'redis://localhost:6379/0'
CELERY_RESULT_BACKEND = 'django-db'
CELERY_ACCEPT_CONTENT = ['json']
CELERY_TASK_SERIALIZER = 'json'
CELERY_RESULT_SERIALIZER = 'json'
CELERY_TIMEZONE = 'UTC'

# Add django-celery-results to INSTALLED_APPS
INSTALLED_APPS = [
    # ...
    'django_celery_results',
    'django_celery_beat',
    # ...
]
```

Don't forget to run migrations for the Celery results backend:

```bash

```

## Creating Celery Tasks

Now, let's create some tasks in your app's `tasks.py` file:

```python
# myapp/tasks.py
from celery import shared_task
from django.core.mail import send_mail
import time
import logging

logger = logging.getLogger(__name__)

@shared_task
def send_notification_email(user_id, subject, message):
    """
    Send an email notification to a user.
    """
    from django.contrib.auth.models import User
    
    try:
        user = User.objects.get(id=user_id)
        send_mail(
            subject,
            message,
            'noreply@example.com',
            [user.email],
            fail_silently=False,
        )
        logger.info(f"Email sent to {user.email}")
        return True
    except User.DoesNotExist:
        logger.error(f"User with id {user_id} does not exist")
        return False
    except Exception as e:
        logger.error(f"Failed to send email: {str(e)}")
        raise

@shared_task(bind=True, max_retries=3, default_retry_delay=60)
def process_data(self, data_id):
    """
    Process data with retry mechanism.
    """
    from .models import Data
    
    try:
        data = Data.objects.get(id=data_id)
        
        # Simulate time-consuming processing
        time.sleep(5)
        
        # Update data status
        data.status = 'processed'
        data.save()
        
        return f"Data {data_id} processed successfully"
    except Data.DoesNotExist:
        logger.error(f"Data with id {data_id} does not exist")
        return False
    except Exception as e:
        logger.error(f"Error processing data {data_id}: {str(e)}")
        # Retry the task
        self.retry(exc=e)
```

## Using Celery Tasks in Views

Now, let's use these tasks in your views:

```python
# myapp/views.py
from django.shortcuts import render, redirect
from django.contrib.auth.decorators import login_required
from django.contrib import messages
from .models import Data
from .tasks import send_notification_email, process_data

@login_required
def create_data(request):
    if request.method == 'POST':
        # Create data object
        data = Data.objects.create(
            user=request.user,
            title=request.POST.get('title'),
            content=request.POST.get('content'),
            status='pending'
        )
        
        # Process data asynchronously
        process_data.delay(data.id)
        
        # Send notification email asynchronously
        send_notification_email.delay(
            request.user.id,
            'Data Processing Started',
            f'Your data "{data.title}" is being processed. You will be notified when it is complete.'
        )
        
        messages.success(request, 'Data submitted for processing')
        return redirect('data_list')
    
    return render(request, 'myapp/create_data.html')
```

## Scheduled Tasks with Celery Beat

Celery Beat allows you to schedule periodic tasks. Configure it in your Django settings:

```python
# myproject/settings.py

# Celery Beat settings
CELERY_BEAT_SCHEDULER = 'django_celery_beat.schedulers:DatabaseScheduler'
```

You can define periodic tasks in your `tasks.py`:

```python
# myapp/tasks.py

@shared_task
def cleanup_old_data():
    """
    Delete data older than 30 days.
    """
    from .models import Data
    from django.utils import timezone
    import datetime
    
    thirty_days_ago = timezone.now() - datetime.timedelta(days=30)
    result = Data.objects.filter(created_at__lt=thirty_days_ago).delete()
    
    return f"Deleted {result[0]} old data records"
```

You can schedule tasks either programmatically or through the Django admin interface after adding `django_celery_beat` to your `INSTALLED_APPS`.

### Programmatic Scheduling

```python
# myproject/celery.py
from celery.schedules import crontab

app.conf.beat_schedule = {
    'cleanup-every-midnight': {
        'task': 'myapp.tasks.cleanup_old_data',
        'schedule': crontab(hour=0, minute=0),  # Run at midnight
    },
}
```

## Running Celery Workers and Beat

To run Celery workers and Beat, use the following commands:

```bash
# Start Redis (if not already running)
redis-server

# Start Celery worker
celery -A myproject worker -l info

# Start Celery Beat (in a separate terminal)
celery -A myproject beat -l info
```

For production, you should use process managers like Supervisor or systemd to ensure Celery workers and Beat run continuously.

## Advanced Celery Patterns

### Task Chaining

You can chain tasks to execute in sequence:

```python
from celery import chain
from .tasks import process_data, send_notification_email

# Chain tasks
result = chain(
    process_data.s(data_id),
    send_notification_email.s(user_id, 'Processing Complete', 'Your data has been processed')
)()
```

### Task Groups

Execute multiple tasks in parallel:

```python
from celery import group
from .tasks import process_data

# Process multiple data items in parallel
data_ids = [1, 2, 3, 4, 5]
result = group(process_data.s(data_id) for data_id in data_ids)()
```
